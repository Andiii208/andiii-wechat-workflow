## 前提条件

### 微信公众平台
- 已注册微信公众号
- 已在 **微信开发者平台** (https://developers.weixin.qq.com) 开启开发者密码
  - 入口：扫码登录 → 我的业务 → 公众号 → 基础信息 → 开发密钥
  - ⚠️ 2025年12月起，开发接口管理已从 mp.weixin.qq.com 迁移至开发者平台
- **IP 白名单** 需添加 Hermes 所在机器的出口 IP
  - 如有梯子，建议梯子 IP 和直连 IP 都加
  - 检查出口 IP: `curl -s ifconfig.me`
  - 微信 API 看到的实际 IP 可从错误信息 `invalid ip xxx.xxx.xxx.xxx` 得知
- 需要：`AppID` + `AppSecret`

## 写作规范

### 风格路由（自动匹配）

不用固定一种风格。根据用户的话题自动判断最适合的写法：

| 用户说的话题关键词 | 自动匹配的风格 | 参考来源 |
|-------------------|--------------|---------|
| 小事/日常/今天遇到/看到/闻到/听到 | **槽边往事风** — 从具体场景切入，思考过程当戏写，极短段落 | A组 |
| 很美/安静/黄昏/夜晚/宇宙/风/云/海/诗 | **MorningRocks 风** — "想象一下"开头，诗意+留白，每节一个金句 | A组 |
| 困惑/选择/毕业/考研/工作/未来/面试/考试 | **我要WhatYouNeed风** — 命名共情，把你的小习惯翻译成心理学概念 | B组 |
| 迷茫/勇气/人生选择/想做又不敢/长文反思 | **杂乱无章风** — 用自己的真实困境示范"高处的迷茫"，脆弱换信任 | B组 |
| 焦虑/拖延/自律/习惯/想不通 | **L先生说风** — 痛点→机制→方案，用认知科学降低自责感 | B组 |
| 失败/被拒/悲伤/集体情绪/输的感受 | **新世相风** — 让"输家"的故事被看见，用真实案例替代说教 | B组 |
| 读书/电影/看到一篇文章/想起一句话 | **MorningRocks × 我要WhatYouNeed混合风** — 跨领域联结+情感命名 | A+B |
| 记录/今天/日常/普通的一天 | **槽边往事 × 杂乱无章混合风** — 个人叙事+自嘲解构 | A+B |

不同风格在以下维度有差异：

| 维度 | 槽边往事风 | MorningRocks 风 | 我要WhatYouNeed风 | 杂乱无章风 | L先生说风 | 新世相风 |
|------|-----------|----------------|------------------|-----------|-----------|---------|
| 标题 | 为什么+日常现象 | 名词短语+留白 | "其实……才是……" | 抽象品质词+句号 | 痛点疑问句+承诺 | 宏大场景+否定常规 |
| 开头 | 场景切入+"我不服" | "想象一下"场景 | 从微小物品切入 | 个人困境自述 | 先否定无效方法 | Sayings编者按 |
| 人称 | "我"极高 | "你"极高 | "我们"为主 | "我"极高 | "你"极高 | "我"低频 |
| 段落 | 2-6行，关键句独立成段 | 中短段落+小标题 | 中短段落+插画 | 极短段落+空行 | 2-4行中等长度 | 极短段落+GIF |
| 配图 | 无 | AI插画2-6张 | 插画/摄影混合 | 手绘线条+GIF | Unsplash头图+分隔线 | 大量真实GIF |
| 金句 | 排比→反转收尾 | 每节一个断言 | 情感命名式金句 | 蓄力→释放单句 | 原理→结论断言 | 他人之口说观点 |
| "你"频率 | 低 | 高 | 中 | 中 | 极高 | 低 |
| "我"频率 | 极高 | 中 | 低 | 极高 | 极低 | 低 |

用户也可以手动指定：`用槽边往事那种风格，主题：今天在食堂`

## Pitfalls

- ❌ **不要在 hermes skills install 超时后反复重试** — raw.githubusercontent.com 在国内常被屏蔽，改用 git clone
- ❌ **不要忘记 IP 白名单有两个可能 IP** — 梯子出口和直连出口，全部加上
- ⚠️ **40164 IP 白名单诊断**：Clash TUN 模式下 `api.weixin.qq.com` 走直连，微信报错里的 IP 是**宽带直连 IP**（`curl ifconfig.me` 看到的是代理出口，两者不同——**以微信报错里的 IP 为准**）；家庭宽带 IP 动态、会不定期失效 → 根治用 baoyu `--remote`（固定 IP 服务器出口）
- 🔴 **40164 直连 IP 失效的免白名单解法（2026-08-16 实测）**：白名单里通常加过**代理出口 IP**（梯子 IP）。Clash TUN 规则下微信 API 被 GEOIP-CN 强制直连（bun/curl 的 HTTPS_PROXY 环境变量都被 TUN 接管、无效），直连 IP 一变就 40164。解法：用 Clash 控制 API 临时切全局模式让微信 API 走代理出口，推完立刻恢复：`curl -X PATCH -H "Authorization: Bearer <secret>" -H "Content-Type: application/json" -d '{"mode":"global"}' http://127.0.0.1:9090/configs` → 推送 → 同样方式 `{"mode":"rule"}` 恢复。Clashmi 配置在 `%APPDATA%\clashmi\clashmi\`（external-controller/secret 在 service_core_setting.json）。⚠️ 推送命令放中间：切→推送→恢复 串成一条 bash 命令，PUSH_EXIT 非 0 也执行恢复；⚠️ `--cover` 路径若图片在 assets/ 子目录要传 `./assets/cover.jpg`，传 `cover.jpg` 会报 `Image not found`（正文图已上传成孤儿素材）
- ⚠️ **IP 白名单填写位置（2026-08 实测，用户曾找不到）**：2025-12 起白名单管理已迁到微信开发者平台，mp 后台只提示"去开发者平台"不给路径——登录 https://developers.weixin.qq.com → **我的业务 → 公众号 → 基础信息 → 开发信息 → API IP 白名单** → 添加微信报错里的 IP → 保存（实测**立即生效**，无需等待）。注意：登录后默认在首页，需先点页面下方「我的业务」卡片进入
- ⚠️ **给用户看 HTML 预览（Windows）**：`open_preview` 面板可能不可见；Hermes 自带浏览器是无头模式用户看不到；`cmd start`/`explorer.exe` 对中文路径经代码页乱码后静默失败 → 兜底：复制到纯 ASCII 路径，或放桌面文件夹 + 图片 base64 内嵌自包含
- ⚠️ **git-bash MSYS 路径 ≠ Windows 原生程序路径**：终端里 `python`/`python3`（Windows 原生）和 `npx bun` 都不认 MSYS 格式——`/tmp/p.txt` → FileNotFoundError；`/d/tools/.../wechat-api.ts` → "Module not found"（文件明明存在）。传给原生程序一律用 `D:/tools/...` Windows 格式；prompt 临时文件写当前工作目录，别写 /tmp（2026-08-03 e2e 实测两个都踩过）
- ⚠️ **PIL 图片处理用系统 python**：Hermes venv 的 PIL 可能损坏（`ImportError: cannot import name '_imaging' from 'PIL'`），系统 python 3.11/3.12 的 PIL 12.x 正常。封面 2.35:1≈900×383 / 内文 16:9≈900×506 / jpg quality 82-85 的裁剪脚本用 `python`（系统）跑
- ⚠️ **图片统一 .jpg 扩展名**：PIL 存 JPEG 内容但命名 .png → wechat-api 报 `Format mismatch: cover.png declared as image/png, actual image/jpeg`（上传成功但难看）；封面/配图按实际格式命名
- ❌ **发布时必须有 cover image** — `--cover` 参数或 frontmatter.coverImage，否则报错
- ⚠️ **`--cover ""` 传空串报 `Error: File path required`（2026-08-07 实测）** — wechat-api.ts 的 `--cover` 空字符串在参数解析阶段直接失败（不是"缺封面"报错，且不提示缺什么）。封面必须先裁好（2.35:1≈900×383）再传真实路径；应急可复用某张内文图中心裁 2.35:1 当封面，不阻塞推送
- ⚠️ **wechat-api.ts（API 方式）接受 .html 输入**（已代码级核实 v1.118.2）：HTML 直接读取，`<section>` 纯片段原样作正文；正文 `<img>` 自动上传（`media/uploadimg`）并重写为 https URL；元数据取 CLI `--title/--author/--summary`，或同目录同名 `.md`（`x.html`→`x.md`）的 frontmatter；`--dry-run` 在取 token 前返回、零风险验证全链路。⚠️ browser 方式仍只吃 markdown（占位符粘贴机制）
- ✅ **API 路径 span leaf 样式保留已实测通过**（2026-08-03）：gzh-design 排版产物 → wechat-api.ts HTML 分支 → draft/add → 公众号助手 App 检查正常（章节标题/衬线金句/下划线/END 分割线/图片/封面全部保留）
- ⚠️ **正文图片必须本地相对路径**（与 HTML 同目录）— 远程非 mmbiz URL 上传行为不确定
- ⚠️ **中文+括号文件名在 bash 中必须加引号**
- ⚠️ **gzh-design 校验必须 0 ERROR + 半角标点 0 WARN** — 半角标点是最高频返工点
- ⚠️ **gzh-design 为 AGPL-3.0** — 修改组件库后对外分发需开源，个人自用无碍
- ⚠️ **Agnes 生图模型（2026-08-03 核查）**：`agnes-image-2.1-flash` 即最新可用免费模型（Agnes Image 2.5 Preview 官网标 coming soon 未上线），**无需改名**；脚本 `external-ai-media-api/scripts/agnes_image.py` 存在（参数 prompt size model，读 Hermes 主配置 .env）；也可直接 curl `https://apihub.agnes-ai.com/v1/images/generations`（OpenAI 兼容，size 支持 "1792x1024"/"4K"）；`/v1/models` 端点不返回模型列表，查模型以 wiki.agnes-ai.com 为准；**401 根因**：key 曾被存成掩码占位符（如带省略号的 sk-hkq...xxx，长度仅 13 字符），真实 key 约 51 字符，从 Hermes 主配置 .env 取
- ⚠️ **gzh-design 装配后必须去标签间空白** — span 之间的换行/缩进会渲染成空格，在 `text-align:justify` 下被拉伸（下划线关键词两侧间隙明显，2026-08-03 用户实测反馈）；文字全在 span 内，安全做法：`re.sub(r'>\s+<','><',html)`，校验前执行（详见 theme-routing.md 调用姿势）
- ⚠️ **去空白后 HTML 变单行，patch 工具失效** — `re.sub(r'>\s+<','><',html)` 之后整个文件只有 1 行，`patch` 工具的多行 old_string 匹配不到（报 "Could not find a match"）。后续要往排版产物里插内容（如图片块），用 **python 锚点 replace**：`html.replace(锚点子串, 锚点 + 新块, 1)`，锚点取段落结尾的 `</span></p>` 片段，每处 replace 前 `assert anchor in html` 防静默漏插（2026-08-03 补 4 张图时踩过）。⚠️ **锚点别跨 span（2026-08-05 实测）**：`"关键词。</span></p>"` 类锚点常因关键词被下划线 span 包裹、句号在另一个 span 里而 count=0 匹配失败——用**纯文本锚点**（不跨标签，如 `"做不完的判断题"`），仍 `assert html.count(anchor) == 1` 防重复。🔴 **纯文本锚点若在下划线 span 内部，图块会被插进 span 里、段落文字中间（2026-08-05 二次翻车，用户草稿箱发现）**：`<span leaf="">做不完的判断题<section>…<img…></section></span></span><span leaf="">。</span>` —— 句号被挤到图片后，微信排版错乱。安全锚点：段落结尾 `</span></p>`，或下划线词完整闭合 `关键词</span></span><span leaf="">。</span></p>`（下划线 span 是 `<span style="border-bottom…"><span leaf="">词</span></span>` 双层结构）。插入后自检 `re.findall(r'<span leaf="">[^<]*<section', html)` 必须为 0；已插坏的修复：提取图块 → 从 span 内删除 → 在段落结尾 `</span></p>` 后重插
- ⚠️ **中文引号归一化只动文本节点，勿碰 HTML 属性（2026-08-05 实测）** — validate 报「半角引号」WARNING 时，直接 `html.replace('"','“')` 会把全部属性引号（`style="..."`、`src="..."`，实测 172 处）也换坏，HTML 直接崩。安全做法：只对 span leaf 文本做配对替换；误换后还原属性引号：`re.sub(r'=“([^”]*)”', r'="\1"', html)`，再跑校验（0 ERROR + 0 WARN 才算过）
- ⚠️ **gzh-design 组件库文件是 CRLF 换行** — read_file 会误判 "Binary file cannot display"（theme-zen-whitespace.md / common-components.md 实测触发，实际是正常 UTF-8 无 null 字节）；用 `python3 -c "print(open(path,encoding='utf-8').read())"` 转储读取，校验脚本 validate_gzh_html.py 不受影响
- ⚠️ **AppSecret 只显示一次** — 启用开发者密码时立刻复制保存，丢失只能重置
- 🔴 **用户手动改过草稿后，重推必须先拉取保留（2026-08-04 实测）**：用户会在公众号后台手动改草稿文字。重推前 `draft/batchget`（no_content=0）拉取**用户版本** HTML，在其上做局部替换（换图用 python 锚点/正则 replace，`assert` 防静默漏插）再推送——**不要用本地旧版直接覆盖**，否则用户修改全丢。注意：用户编辑过的 HTML 里 span leaf 可能被微信编辑器改坏（漏包），拉取后跑 validate_gzh_html.py 检查，缺 leaf 手动补
- 🔴 **喜茶风配图 = 「拙趣」手绘风，不是宣纸水墨印章（2026-08-05 用户两连否）** — `andiii-heytear-style` skill 的旧四件套（宣纸底/水墨晕染/茶渍/朱砂印章）被用户否：「根本不是喜茶风」「完全不是喜茶风」。联网调研（Design360°/数英/FoodTalks）确认喜茶 2025 真实视觉是**「拙趣」风**：拙感手写体、圆钝简笔画、儿童般稚拙笔触、**刻意保留铅笔草稿线**、破除网格排版、松弛不刻意、大留白、低饱和自然色（米白/浅灰褐/浅豆绿）、有「活人感」不精致不匠气。**绝对不是**传统水墨国画/书法字/印章/做旧宣纸，也不是性冷淡现代工业设计（极简白杯+茶烟同样被否）。试水 prompt 方向：「圆钝拙趣的简笔画{茶器}，笔触像小孩随手画的，线条粗细不均、边缘有点抖，保留铅笔草稿线，手绘温度感…避免水墨国画，避免书法字，避免印章，避免做旧宣纸，避免茶渍」。⚠️ GitHub 有专门 skill：`Hchen1218/heytea-style`（喜茶风格儿童简笔画海报）——但它是**图生图**向（真实物件摄影锚点 + 简笔画小人叠加），**文生图场景不能照搬**（用户明确：「我不要真实摄影质感的，我就要插画」）。⚠️ skill 本身是 user-owned 需 `hermes curator adopt` 才能改；改之前生成喜茶风一律按本条目手动编译。
- 🔴 **配图意象纪律：意象匹配 > 画风（2026-08-05 六轮否定后用户拍板）** — 配图被否 6 轮（zine→喜茶水墨→喜茶极简→喜茶摄影→喜茶插画→潦草手账茶意象）后，用户点破根因：「你非要沿用茶这个意象吗？我觉得它并不是一个很适合我这个推文的意象」。**歌单/音乐类推文配图不用茶/器物意象**，用**听歌本身的物件**：网易云红心、黑胶唱片、磁带、耳机、声波线。通用原则：意象从文章主题的「本体」里长出来（歌单→红心/唱片/磁带），不是外部硬套一个「好看但无关」的隐喻（歌单→茶）。验证过的完整意象映射 + 15 个过质检门的 prompt 模板见 `references/playlist-illustration-imagery.md`。
- 🔴 **配图风格确认节奏：先 1 张试水再批量（2026-08-05 实测）** — 风格/意象不确定时，**先出 1 张试水图给用户确认方向，过了再批量生成**（本次黑胶+红心试水一次通过，前面 6 轮都是闷头批量 15 张后整批被否）。试水通过的 prompt 模板直接复用（改意象词），不要每张重编。
- 🔴 **线条/极简风配图也必须具体场景意象（2026-08-06 实测）** — 黑白针管笔（antibes-holiday）试水：抽象线条碰撞被否「感觉这图有点抽象了呀」，换具体场景（长桌两端背影+空杯，对应沉默/没说的话）通过。任何风格都落到可识别的人/物/叙事，抽象隐喻线条不适合公众号配图；针管笔 prompt 编译要点（Wan2.7 不收参考图→文字化线条规格）见 references/image-style-routing.md 调用姿势第 6 条。
- 🔴 **"面对面"构图必须视觉可读（2026-08-07 实测）** — 用户确认意象"小桌面对面"后，两人纯背影分居左右被否「你不是说是小桌，面对面吗？你这不是面对面呀」——纯背影看不出相对关系，只适合"并排/同方向"意象。面对面要用**侧面剪影相对**（一人面朝左、一人面朝右，头互相朝向对方，中间小桌）。⚠️ Wan2.7 出图常不遵守"不画五官/侧脸"和"横构图"指令（会把纯背影画成侧前方+侧脸、竖构图），每张必须 vision 复核兜底，违规就重画并强化措辞（"绝对不画五官、侧脸、鼻子、手"）。单张连被否 2-3 次后停止猜测，用 clarify 列候选方向（用户可能选"算了就这张"，直接采纳继续流程）。
- ⚠️ **并发批量生图偶发失败（2026-08-07 实测）** — 一次并行 4 张 image_generate，其中 1 张 ConnectionResetError（tokenrhythm→agnes 自动 fallback 也失败）；相同 prompt 原样重试仍失败，精简改写 prompt 后成功。属瞬态网络问题，换 prompt 变体重试即可，不要当长期故障记录。
- 🔴 **音乐/文艺类推文配图：zine 拼贴优先（2026-08-04 用户拍板）**：水彩风被用户否「特别丑」，zine 拼贴获赞「特别有艺术感」。1:1 方形图保持**单一视觉焦点**（勿堆多张照片）；金句不做图片卡，用排版金句块
- 🔴 **针管笔适配范围修正（2026-08-07 实测被否）** — antibes-holiday 路由到「观点/深度随笔」，但《认识很容易朋友很难》（共情+思辨向软观点文）被否「我不想要这个风格」，用户改选 Zine 拼贴。针管笔适合硬观点/讽刺/立场表达（《后来我逐渐收起了自己的观点》通过），**不适合情绪共情向**；共情向观点文默认优先 zine
- ⚠️ **zine 微文本乱码（2026-08-07 实测）** — zine 引擎的微文本（数字日期）在 Wan2.7 生成无意义长数字串「101015667 19650 2097,」乱码感。微文本要么极小/模糊/几乎不可读（半可读碎片），要么直接 almost textless；长数字串会被用户当乱码。生成后 vision 复核专查左下角微文本
- 🔴 **zine 艺术感配方：拼贴层次 > 留白（2026-08-07 三版试水定稿）** — zine 配图连调两版才过：v1 单一旧照片居中贴纸面 → 否「不够艺术感」（太干净，只有一张照片，缺 zine 的破碎拼贴层次）；v2 85% 留白+视觉簇挤左下角 → 否「太空了」（**艺术感 ≠ 大留白**）；**v3 通过配方**：65% 留白 + 视觉簇横贯中下部占画面约 40% + 4-5 层碎片错落拼贴（主体照片碎片 + 附属小碎片 + 斜穿半可读英文纸带 + 灰绿胶带 + 半透明撕边纸片）+ 撕边/油墨渗开/边缘洗淡/轻微套印错位 + 低饱和灰绿 wash。⚠️ 与 2026-08-04「1:1 方形分享图保持单一视觉焦点」不冲突：那是方形分享图规范，16:9 横版内文图用多碎片拼贴；方形图仍单焦点
- ⚠️ **配图风格选择：一开始就列全部引擎（2026-08-07 实测）** — 用户问「一共有哪几种风格？」= 给 3-4 个预设选项不够，用户要看到全部候选。clarify 选择时一次列全（水彩/zine/潦草/极简/喜茶/针管笔/CRT），别只给推荐+2 备选
- 🔴 **拼贴图同一意象只用单张照片碎片（2026-08-07 两次被否「图片里面的图片重复了」）** — zine 拼贴里同一主题的多张照片（大集体照+小背影照、三张门的照片、孤岛主图+小船接近小图）全部被否：用户不接受「图片里的图片重复」。正确做法：**一个意象 = 一张主体照片碎片** + 纸带/胶带/文字纸片/半透明撕边纸片做装饰层次（装饰物不算照片）；prompt 必须显式写「Exactly ONE single torn photo fragment, absolutely no other photos, no second photo, no small photos」并加强措辞（Wan2.7 默认会自动加小照片，img1 重出两次才干净）。⚠️ **照片碎片本身要横向**：竖版照片碎片贴在 16:9 画布上 = 竖版感被 vision 检出（铁轨/平行线图重画成「照片碎片本身横向、铁轨斜穿画面」才过）。封面同样遵守单张照片规则（孤岛封面 v1 因「孤岛+小船」两张照片被否重画）
- ⚠️ **check_engine_prompt.py 规避词必须逐词「avoid X」成串（2026-08-04 实测）**：质检门的豁免逻辑 `_is_avoided` 只认「avoid / 不要 / no 」前缀与规避词**连续相邻**（子串匹配）。写 `Avoid neon glow, high saturation, 3d render…` 逗号列表 → 只有第一个词被豁免，其余全部误判 FAIL（实测 8 个 prompt 全 FAIL）。必须写成 `avoid neon glow; avoid high saturation; avoid 3d render; …` 分号分隔、每个规避词前都带 avoid
- ⚠️ **check_engine_prompt.py 纸感词也是硬检测（2026-08-05 实测）**：质检门要求 `cold-pressed paper` / 纸纹 / 旧纸 类词显式出现——只写 `aged cream paper + matte absorbent paper with fiber texture` 会被判 FAIL「缺纸感词」（5 个 prompt 挂 2 个，补 `cold-pressed paper texture with visible paper grain` 后 PASS）。所有风格引擎 P1 画布段都写上显式纸感词，别省
- ⚠️ **Wan2.7 拼贴/多格画板退化（2026-08-10 实测，1:1 与 16:9 都会中招）** — 封面分享图（1:1）首版把单焦点构图画成左右分栏拼贴（抽象晕染块+小风景缩角落）；**16:9 内文图同样会退化**：img2 辽阔远山被画成 2×2 四格画板、img3 村落被画成 3 连格，vision 复核抓出后重画才过。修复：P2 显式写「单一完整的远景风景画，不是拼贴，不是多格画板：一整幅连贯的画面，无边框分割，无抽象色块，无水彩渍拼贴」，P4 追加 `avoid collage; avoid multi-panel; avoid abstract color blocks`；**每张生成后必 vision 复核单焦点/连贯画面**，初版命中率约 2/5。🔴 **纸张/日程/记事本类意象最高危（img9 空白日程纸被画成 2×3 六格，模型把每个纸面元素拆成独立面板）**：重画强化为「只有这一张纸，无边框分割，无第二张纸，无抽象色块」才过；相册/旧书/笔记本/日历/名片——凡"纸上的东西"（照片、涂鸦、文字）都倾向每元素一格。✅ 同批成功范例（可复用）：img7 相册意象（摊开旧书/相册 + 一张小照片 + **照片边缘水彩晕染渗开** + 纸面淡墨山影漫延）一次过——用"晕染渗开"把照片与纸面融成单一画面，避免多元素并列；img8 窗外意象（窗内桌角水杯一角 + 窗外山海）一次过——用"窗框"统一室内外两个世界，是"工作与生活不打架"类主题的复用意象。⚠️ 用户说「配图再多一点」= 先列未配图意象块清单逐块补（每逻辑意象块一图），新图插入用纯文本锚点 + assert 防漏插，重推草稿后必须删旧 media_id 防堆积
- ⚠️ **PIL 存 JPEG 前必须 `.convert('RGB')`（2026-08-10 实测）** — Wan2.7 输出 RGBA PNG，直接 `save('x.jpg')` 报 `KeyError: 'RGBA'`（hermes venv 与系统 python 的 PIL 均如此）。裁剪/转存统一 `Image.open(p).convert('RGB')` 再 save；封面裁剪优先用引擎自带 `scripts/crop_image.py`（已处理此坑），手写裁剪脚本时别漏
### 写作陷阱（补充 andiii-writing-style 未覆盖但会话实测的）

- **概念列表/对比类主题先讨论再动笔** — 用户给"旅游/旅行/度假"这类多概念主题时，意图可能是"想讨论三者之间的区别"，而不是"写一篇文章"。先展开讨论（拆概念、给框架、抛角度），用户认可讨论后，文章方向从讨论结论里长出来再动笔。2026-08 实测：拿到"旅游/度假/旅行"直接写了一篇旅行文章，被纠正"我是说想讨论一下"。判断规则：主题是单个意象/事件 → 可写；主题是"多概念的对比"→ 先讨论。
- **POV 选错** — 用户拒绝虚构的"我"。没有用户提供的真实个人素材时，叙事主体一律用"你"（第二人称，对读者说话）。只有用户给了具体的亲身经历（如"大二那年我在操场走了三个小时"），才用"我"。用错"我"比用错"你"更致命，因为被识破是编的后整篇文章可信度归零。**旁观者≠当事人（2026-08-06 两连否）**：素材用"发现/看到/意识到"类动词 = 用户是旁观者，冲突/争端只作**现象**抽象写（"观点不一样，是真的会吵起来的"）；"吵到最后/谁也没赢/一方不说话了"式过程描写即使无主句也像当事人视角，被否"我也没有争论过"。完整案例见 references/style-rejection-cases.md 案例2。
- **扩写方向错误** — 用户接受"深挖一层"（分析why），拒绝"铺开细节"（更多场景描写）。改稿时宁可加一层分析，不要增加场景描写的量。多一个层次的洞察 > 多三句场景描写。
- **照片级构图不合适** — Agnes / baoyu-image-gen 的概念图生成效果最好的prompt是"极简、概念型、写意不写实"。避免要求"现实主义"/"照片级"。
- ⚠️ **歌曲/专辑事实必须搜索核实后再写（2026-08-04 实测）** — 用户会逐项核对。动笔前每首歌查：所属专辑+年份、词曲作者、歌词主题、**要引用的歌词原句**（一字不差）。金句式否定断言高危：想写《飞机场的10:30》"没有一句'我想你'"、实际歌词开头就有「我好想你」——差点写出事实错误。写法改对比：「最打动我的不是那句'我好想你'，是可乐剩一点给你」。专辑封面图获取/核查流程见 references/music-article-workflow.md。
- ⚠️ **口头素材先确认指代（2026-08-04 实测）** — 用户说「飞机场的话是第一首歌」，被误理解成「用户听到的第一首」写进文章，纠正后才知道是指「陶喆出道的第一首歌」。用户口述的简短素材（尤其省略主语的），动笔前确认含义/指代，不确定就不写。
- ⚠️ **预设场景细节（2026-08-04 实测）** — 普适主题（"大学生与熬夜"）也预设不得：直接写了"宿舍灯关了/明早八点有课"，用户当场纠正"现在是暑假，我根本不在宿舍"。任何地点/时间/季节/身份处境的细节，动笔前先问，不确定就不写。宁可少场景，不写错场景。
- ⚠️ **素材先行对直接指令同样生效（2026-08-04 实测）** — 用户说「写一篇XX主题的推文给我」≠ 可以跳过提问直接动笔。收到主题先问 3-5 个素材问题（场景/感受/具体画面），拿到锚点再写；跳过提问直接写会被点名「没有按我规定的流程来」。
- 🔴 **方向确认 ≠ 素材确认（2026-08-07 实测，用户怒骂「你真的走了工作流的流程吗，他妈的简直是稀烂」）** — 本次流程：搜素材→给素材清单+写作方向→用户答「泛大学生、不说教」（方向修正）→以为可以动笔，直接写了一版全文，被点名流程稀烂。根因：问的是**方向性问题**（读者定位/标题/是否说教），**素材性问题（你什么时候有这种感觉？有没有具体画面？你自己的看法？）一个没问**。判定规则：用户回答里没有「具体时间/地点/画面/亲身经历」颗粒，素材先行就没走完，不许动笔。授权「多去网上搜索浏览」只是补充例子的许可，不是跳过问本人素材的许可——网上例子是补充，不是替代。
- 🔴 **给读者（"你"）预设行为也是预设场景（2026-08-07 实测）** — 无锚点时写了「开学那阵子朋友圈都在晒新宿舍合影，你也会发一条」——替第二人称读者编了「你也会发」的行为，同样构成编造。预设细节不限于"我"的处境，连"你"的通用行为也不能脑补。没有锚点，场景只能停在现象级描述（座位不固定/课表错开/岛与岛之间没有船），不落到具体行为。
- 🔴 **共情向零规训（2026-08-04 用户拍板）** — 「我不劝你早睡」「你大概不是懒」「没什么好自责的」看似共情，实为规训姿态：嘴上说不劝，立场还是「你该睡」。用户明确：「不要写什么我不想劝你早睡，我并不想要说教」。共情 = 理解 + 留白：不评判、不总结、不给方案，连「我不劝你」这类元评论都删掉；「怎么办」段（如「给白天腾点位置」）也是变相说教，共情向一律砍。
- 🔴 **AI 味根因在深度不在词句（2026-08-04 实测）** — 用户说「不够精彩、不够深入、有点AI味」时，根因是科普+劝解模板（只写表层机制 + 方案段），不是个别词句。修复链：① 挖三层机制：表层（白天时间不是你的）→ 中层产品机制（信息流下一条期待 = 老虎机，解释"为什么是刷手机"）→ 深层心理（睡眠 = 关机 / 醒来又是别人的一天，解释"困了也不肯闭眼"）② 共情向砍掉全部「怎么办」③ 「更好的表达」升级点：开头用动作循环（划开/锁屏/再划开）代替静态场景描写；核心洞察挖到心理层（深夜刷别人的生活 = 找参照，「是不是只有我的一天，过成了这样」）；标题承诺要在正文兑现（标题说「别人的一天」，正文必须写清它意味着什么）。
- ⚠️ **概念/研究引用先核实出处再写（2026-08-04 实测）** — "报复性熬夜"这类心理学概念引用前先搜证：来源是 2014 年微博创造的说法（revenge bedtime procrastination），学术源头是荷兰学者 Kroese 等 2014 年《Frontiers in Psychology》的 bedtime procrastination 论文（PMC4062817）。写"XX概念/研究说"必须有真实出处，用户会逐项核对。核实锚点可存 references/ 供复用。
- 🔴 **AI 味形态清单（2026-08-05 信息爆炸史实测，逐条被用户否）**：
  - 模板化结构：阶段平均分配篇幅+每段金句收尾 → 「很ai，质量很差很差」
  - 每段点题/定义句（「那是黑盒最早的形态」「这才理解什么叫信息的海洋」）→ 「ai味太冲了」
  - 满篇「你」第二人称轰炸 → 「ai味太冲了」（正确做法：无主句为主，「你」全文≤5处）
  - 换掉已获认可的思想线（黑盒→框）→ 「还变差了」。思想线获认可后只换写法，不换思想
  - 碎碎念网络口语（「怎么办？百度。」）→ 「整体文风我也不喜欢」
  - 用户要的：细节详细（具体物+画面：作业本/蓝色标题/压低声音/边角卷起来的卷子）+ 真实网上例子 + 保留已认可思想线
- 🔴 **文风被否 2-3 次后停止猜测，直接要参考（2026-08-05 实测）**：列 2-3 个候选文风（槽边往事白描/我要WhatYouNeed共情/朴素叙述）或请用户甩一篇文风对的公众号文章链接。继续产出新版本 = 空转，浪费用户耐心。完整案例见 references/style-rejection-cases.md
- 🔴 **思辨必须织进动作/体验，禁止贴解说词（2026-08-05 实测）** — 用户否「没有很好的融合进去」：先场景后「现在想想，累的不是信息多……」式解说段 = AI 味信号。正确做法：思辨化成角色的动作/体验（「只能一直盯着」「每看一条都要判断一次'这条要不要紧'」「连掂量的资格都没有」），让读者自己品到，不喊破。全文点破的「道理句」≤2。
- **素材提问只问一轮，拒答后转自我深挖（2026-08-05 实测）** — 素材先行问 3-5 个问题后，用户说「没什么好回答的，你自己去深入思考思考」——立即停止追问，转入思辨层：输出「这个主题背后在发生什么」类的新洞察（如猎人→哨兵/判断负担/责任转移/验收员）让用户拍板，认可后再动笔。反复追问 = 消耗耐心。
- **回忆文可用「姿态演变」作主线（2026-08-05 成功结构）** — 找→听→盯→收：每阶段「人对待信息的姿态」变化就是推进力，思辨与场景一体；不平均分段，素材最多的阶段最重。用户最终认可的版本即此结构。信息/媒介类主题的思辨角度库 + 可复用素材见 references/info-overload-narrative.md
- 🔴 **旁观者≠当事人（2026-08-06 两连否）** — 素材是"发现不同的观点有时候会引起争端"（发现/看到/意识到类动词 = 旁观者立场），不是"我跟人吵过"。写"一开始还想着争"被否"我也没有争论过"；连无主句的"吵到最后，谁也没赢。就算一方不说话了，关系也远了"仍被否——**没有主语也像当事人视角**。写法：冲突只作**现象**出现（"观点不一样，是真的会吵起来的"），过程/结果描写一律删；思辨用抽象机制句承接（"人急眼的时候，争的其实已经不是那件事了。争的是自己"）。
- 🔴 **过于自然=刻意AI味（2026-08-06）** — 用户否"过于自然了，反而显得有点刻意"。根因是句子密度：~600字里8句"聪明句"（句句短句断言、句句有嚼劲），读起来像打磨过的文案。修复：聪明句砍到≤3句、其余冲淡成普通说法；加口语毛刺（什么的/大概/想了想）；段落长短不均（check_prose.py 句长变异系数 WARN 是信号，0.42 即偏均匀）。自然的粗糙感 ≠ 设计的自然。⚠️ **口语毛刺别堆砌（2026-08-07 修正本条）**：满篇「其实/好像/隔三差五/好不容易/也就这样了/吧」被否「过于生活化，反而显得很AI」——刻意唠嗑是AI最擅长的伪人味，与聪明句过密同罪。毛刺全文≤2-3处、自然带出即可；句子主体写干净书面，让思考立起来。再下一步是加文采与思辨，见「共情文再深入」条目。
- **否定式自我辩解是AI味** — "也说不上怕。就是觉得没意思。"（先假设读者会揣测"你是不是怕"再自我否定）被否，改成"也说不上为什么。就是觉得没意思。"（承认说不清，不辩解）。"不是…是…"句式全文3次即套路（check_prose 翻案腔变形会标），注意变形分散。
- **隐喻的施动对象必须合理** — "有些话放着放着，自己就凉了"用户看不懂：话不会凉，凉的是"想说的劲"。对象错位的隐喻直接换直白说法（"当时没说，之后也就不想说了"）。
- **删段必须重焊逻辑链** — 删掉"吵到最后谁也没赢"后衔接断裂+思辨变薄，被否"衔接不够流畅，思辨也差一点"。用"争的是自己"作桥焊回：争的不是那件事→争的是自己→那时一致是借来的（没长出自己）→观点=自己碰不得。删思辨段后用等价抽象机制句补位。
- **用户否一个词 → 全文所有出现处全删（2026-08-06）** — "自己人"开头结尾各一次，用户说"我不喜欢"——只改一处还会被再纠。被否的表述做全局清理，别留任何一处。
- **被批"没之前好"→ 回退已认可的旧版骨架（2026-08-06）** — 深挖版被否"还不如之前写的好"（根因：新思辨建立在编造的"我争过"上+另起段落贴解说词）。不要重新发明结构：回到用户认可的 v1 骨架，只做被点名修正，深挖句放回原位不加段落。v1 骨架+局部修正的组合最终通过。
- **结尾偏好极简三句收（2026-08-06 用户拍板）** — 用户自己改出的结尾："大多数时候，话到嘴边又咽回去。说不上是成长还是妥协。只是慢慢习惯了。"——三句、最后短句收住、不再展开解释。给候选结尾时注意："不想说了"类结果描述听着像人变冷淡，释然/留白感（"不说也可以"）更贴用户；最终用户选的往往比所有候选更短。
- **素材有阶段颗粒度，不能跨阶段迁移（2026-08-07 实测）** — 用户素材分阶段（初中：玩得来的同学观点大致相同；长大后：明星/球星/热点/三观差异）。把长大后阶段才出现的例子写进初中段被否「初中的时候不要写那个球星啊、明星啊啥的，就说自己跟周围玩得来的同学，大家的观点大致相同」。用户素材里出现过的例子只能用在对应阶段；前期阶段宁可用概括，不挪后期素材。
- 🔴 **大众感受类主题：通用场景也是编的（2026-08-07 实测）** — 用户给"大众感受"（无个人经历素材）时，"上课坐你旁边的/食堂排你前面的/电梯里的三十秒"这类以"你"开头的通用场景被批"事情很假""场景很假"；连"恰到好处地走开"这种为好看写的文艺腔也是假。共情不靠场景，靠**直接说破共有的感受与判断**（"大学里认识很容易，朋友很难"）。用户没给过的具体画面一律不写；无画面直说反而最共情。与上面"给读者预设行为"是同一纪律的两面：场景细节和"你"的行为都不能脑补
- ⚠️ **科普素材在共情向文章 = AI 味（2026-08-07 实测）** — 90小时定律、接近效应这类研究/数据被批"很ai"（科普感/知识帖感）。研究背书只适合知识输出向（模式B）；纯共情向（用户要"感同身受"）砍掉一切研究佐证，哪怕素材本身真实可考。用户要的是同感不是知识点
- 🔴 **共情文「再深入」= 锋利命题 + 文采，不是科普（2026-08-07 实测）** — 时间观功利化深入版后仍被否「显得没有文采，也不够思辨」。两条正向解法：① **思辨 = 现象层锋利命题**，把共有感受拧成一句让读者停一下的话（「大学安排了最多的相遇，却生产出最少的友谊」「认识空前地便宜，朋友空前地昂贵」「人一旦被安排了目的，就会把自己收起来」「友谊只长在那些无目的的时间里」）——不是研究结论、不是机制解释，是读者能直接对照自己的判断；② **文采 = 意象 + 对仗 + 精准词**（「每一分钟都标好了用途」「活动一散，人也就散了」「换不来学分，进不了简历，只长在那些无用的时间里」）。打磨顺序：极简老实版 → 再深入（加一层机制洞察）→ 去口语化 → 命题化+文采化，每步用户点头再走下一步。完整 7 版迭代史与最终稿见 references/friendship-article-rejection-case.md
