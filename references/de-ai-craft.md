# 去 AI 味手册（公众号版，de-AI craft）

> 2026-08-04 建。配合 humanizer（34 模式扫描，管**语言层**）使用。本手册补两个缺口：**结构层手术**（humanizer 不管的段落骨架问题）和**声音层**（AI 味的根本来源）。并解决 humanizer 的"用 I"建议与公众号**第二人称雷区**的冲突。
>
> 核心洞察（writehybrid 2026）：**一致的声音，反直觉地比完美中立散文更不统计平均——所以读起来像人**。AI 味 = 太均匀 + 太正确 + 太完整。

## 〇、输入端杠杆（2026-08-04 用户确认，最高优先级）

**AI 味不是写出来的，是没东西可写时硬写出来的。** 只要输入是"主题"而不是"素材"，AI 就只能用语言技巧填充空白——排比、升华、金句、正反论证。这些就是 AI 味。

输出端工具（humanizer 删除 / 风格指南模仿）都是给嫌疑人找罪证，删狠了文章会坏（用户踩过"矫枉必过正"）。真正的杠杆在输入端：

1. **素材先行**：收到主题先别动笔，问 3-5 个针对性问题（"这事发生在什么时候？当时什么感觉？有没有一个具体的画面？"），挖出真实颗粒再写。只给主题没给素材 → 先坦白缺什么，不硬写。
2. **写作意图三问**：写给谁看？想让他读完产生什么感觉？为什么是今天写这篇？三个问题答不上来就不写——意图会把语言拉向具体。
3. **完备性 ≠ 人味**：AI 什么都写到，人是有选择的——有的地方写三行，有的地方就三个字，有的地方故意不说。

## 一、AI 味三层模型

| 层 | 表现 | 管它的工具 |
|---|---|---|
| 语言层 | 三连排比/强行升华/"值得注意的是"/em dash/同义词轮换/翻案腔/冒号滥用/黑话 | humanizer（34 模式）+ **check_prose.py 机器门（2026-08-06 接入）** |
| 结构层 | 每段"观点→例证→升华"、首尾填充句、段落长短均匀、每段都有金句 | **本手册第二节**（新） |
| 声音层 | 一切都太正确：无立场/无矛盾/无毛刺/无私人性/无意外 | **本手册第三节**（新） |

## 二、结构层手术刀（humanizer 不覆盖）

1. **删首尾测试**：删掉某段第一句和最后一句，如果段落还通顺——那两句就是填充，删（edubrain 2026）
2. **删"只为引出下一句"的句子**：一句只承担"铺垫"功能 → 删掉它，把下一句改写成独立句
3. **拆"完美段落"**：AI 段落太完整（观点+例证+收束齐全）→ 拆开：观点单独成段，例证跟上，**不要每段都收束**——有的段就该戛然而止
4. **去掉"每段一金句"**：连续 3 段都以金句收尾 = 强 AI 味。金句是稀有品，全文 1-2 句足够，其他段落在中间停住
5. **不均匀化**：长短句交替（一句 8 字 + 一句 30 字）；段落长度故意错落（一段 3 行、下一段 1 行）；不要每段一样长
6. **改结构不改词汇**：检测器抓的是可预测的句式模式——换句子顺序、换开头方式、换节奏，比换同义词有效 10 倍（justdone 2026）
7. **删过渡词**："所以/但是/然而/更重要的是"开头句，直接切入内容

## 三、声音层（AI 味的根本）

1. **立场贯穿**：全文选一个态度（这件事让人惦记 / 它被低估了 / 想学但学不会），让态度决定选词和强调点——**拒绝"完美中立"**（writehybrid）。⚠️ 立场 ≠ 负面表达：用"惦记/珍惜/想不通但放不下"这类暖立场，不用"烦/讨厌"（公众号忌讳负面表达）
2. **承认矛盾**：写"既…又…"的真实复杂（"惦记，但又不敢靠近"），不要一路正确到底。⚠️ 矛盾也走暖调：不用"又烦又无奈"，用"想抓住又怕抓不住"
3. **允许不完美**：真实的文字有纹理——偶尔的口语、突然的细节、一句没说完的话、一个跑题的括号。别把每句话都打磨圆润
4. **具体 > 抽象**："孤独"→"周日傍晚空荡的食堂二楼"；"压力"→"手机还剩 3% 电量的时候"（用用户给的素材，不编造）
5. **少一点"不过/但是"**：AI 习惯先肯定再否定。直接说，别每次都转折
6. **结尾不升华**：AI 最爱结尾拔高。真实的人结尾是"就到这里"或一个具体的小细节——这正是你的公众号落款风格

## 四、第二人称适配（重要！）

humanizer 的"Add voice"建议（"Use I when it fits"、"I keep coming back to..."）**在公众号场景下不直接用**——你的写作雷区是代笔禁止"我"叙事，统一用**"你/我们"**：

| humanizer 建议（第一人称版） | 公众号适配（第二人称版） |
|---|---|
| I genuinely don't know how to feel about this | 你说不清这是好是坏 / 我们谁也说不好 |
| I keep coming back to... | 你总会绕回那个画面 |
| Here's what gets me... | 真正戳你的是 |
| I've accepted suggestions that... | 你也干过这种事： |

原则：**保留 humanizer 的反 AI 味操作（删模式），替换其 voice 示例的人称（"我"→"你/我们"）**。立场/矛盾/毛刺都可以用"你/我们"表达。

## 五、操作流程（写作层第⑦步细化）

```text
1. 初稿 → humanizer 扫描 34 模式（语言层清理）
2. **机器门**：跑 `python D:/tools/hermes/skills/writing/human-writing/scripts/check_prose.py <稿件.md>` — 硬禁令（冒号非引语/破折号/翻案腔/黑话/模型路标/硬停词）清零；WARN 项人工判断
3. 结构层手术：删首尾填充 / 删引子句 / 拆完美段落 / 去金句堆叠 / 不均匀化
4. 声音层检查：立场在吗？矛盾在吗？毛刺在吗？结尾升华了吗（删）？
5. 人称检查：全文"你/我们"，无"我"叙事（引用/对话原文除外）
6. 二次自问：哪句最像 AI 写的？—— 删/改它
7. 交付全文给用户审阅
```

## 六、机器质检门：check_prose.py（2026-08-06 接入）

> 吸取自 `human-writing`（KKKKhazix，981⭐，MIT）。文字版质检门，与图片的 `check_engine_prompt.py` 对称——**硬禁令机器可查，不再全靠 agent 自觉**。

```bash
# 支持文件或 stdin
python D:/tools/hermes/skills/writing/human-writing/scripts/check_prose.py 稿件.md
python D:/tools/hermes/skills/writing/human-writing/scripts/check_prose.py - < 稿件.md
```

**硬禁令（FAIL 项，必须清零）**：中文冒号/英文冒号（引出人物原话除外）、破折号（`—`/`——`/`–`）、硬停词（说白了/说穿了/先说结论）、黑话（赋能/抓手/商业闭环/底层逻辑/顶层设计/降本增效/全链路/组合拳等 26 词）、模型路标（值得注意的是/需要指出的是/更微妙的是等 6 词，正则捕捉）、翻案句（不是…而是/并非…而是/不在于…而在于/与其说…不如说/表面…其实/看似…实则 等正则）。

**WARN 项（人工判断）**：引语冒号、语境黑话（沉淀/颗粒度/对齐/协同/方法论/闭环等 14 词，本义准就留）、疑似翻案腔变形（以为…其实/回头才发现/A不重要重要的是B/真正…的是/不只…还 等）、三连以上同构排比、抒情词（安放/抵达/微光/褶皱/滚烫 等≥2 处）、名词化句式（进行了…/实现了…提升/完成了对…的 等）、连词密度（>7‰）、句长变异系数（人写长短差大，模型句长接近）、短段连击（≤24 字单句段连续 4 段）、重复开头词、隐喻簇（温度/战争/建筑/仓储/赛道/机器/海洋 等借喻≥3 类密集出现）、「」括号金句过密。

**与碎碎念体的边界**：脚本禁的是**模型腔修辞动作**（翻案/排比/冒号/破折号/黑话），不禁风格——第二人称、无主句、口语零结构、金句≤1 全部兼容。改违禁句时先找回它原本想说的事实，用普通句子说，不要找另一种漂亮句式替换。
